# 架构

> 人生画布 · Life Canvas
> 这篇讲**为什么长成这样**。字段级的数据契约在 [`DATA-FORMAT.md`](DATA-FORMAT.md)；
> 原生壳的坑在 [`macos-shell.md`](macos-shell.md)。

<details>
<summary>English summary</summary>

The core idea: a life is a **graph**, not a canvas. The canvas is only one view of it.
Three dimensions (themes, stages, time) sit over one dataset; five views read from it.
Everything is local-first: no account, no server, no telemetry, no runtime dependency.
</details>

---

## 1. 产品内核（技术上的翻译）

这一句话决定了整个架构：

> **普通画布里，画布是主对象，节点是画布上的图形。
> 人生画布里，图谱是主对象，画布只是「当前这个面」的一张视图。**

由它推出三条不可动摇的技术约束：

| 约束 | 为什么 | 违反的后果 |
|---|---|---|
| **坐标是全局唯一的**，不属于任何「面」 | 人对"那个东西在那儿"有空间记忆 | 同一目标在不同面跳位置，核心体验崩塌 |
| **面（主题 / 阶段）是一等公民**，画布只是它的一种视图 | 面是人生阶段，不是视觉框 | 面退化成文件夹，"阶段感"消失 |
| **数据层不认识画布** | 画布是视图，不是数据本身 | 换 UI = 重写产品 |

第三条落到代码上就是 `src/model/` 不 import 任何上层模块 —— 它可以被拿去当
库使（见第 4 节的目录说明）。

## 2. 目录

```
src/
  model/      类型定义、内存图谱、派生查询 —— **不依赖任何上层**
  persist/    IndexedDB、加密、导入导出
  search/     bigram 倒排索引（跑在 Web Worker 里）
  canvas/     视口、空间索引、文本排版、Canvas 2D 渲染、手势
  views/      五个视图 + 检视面板 + 详情页
  app.ts      应用总装：状态、事件、原生通道
  app/        从 app.ts 里切出来的三块（见下）
  i18n/       文案层（键 = 英文 slug，中英文同表）
  data/       示例空间与压测库
  ui/         DOM 小工具
  platform/   与原生壳的通道（web 侧）

macos/        原生外壳（WKWebView + 工具栏 + 菜单）
scripts/      构建与体检脚本
tests/        366 条单元测试
docs/         数据格式契约、macOS 壳笔记、本篇
```

**依赖方向是单向的**：`model` ← `persist`/`search`/`canvas`/`views` ← `app`。
`model` 不 import 任何上层，所以那部分可以单独拿走用。

### `src/app.ts` 与 `src/app/` 同名

这两个**故意重名**，不是笔误：

- `src/app.ts` —— 应用总装。仍然是全局状态的唯一持有者，
  视图、事件、原生通道都在这里汇合。
- `src/app/` —— 从 `app.ts` 里切出来的三个独立模块：
  `selftest-hooks.ts`（自测钩子）、`settings-menu.ts`（设置面板）、
  `splitters.ts`（分隔条拖拽）。

为什么是「同名文件 + 同名目录」而不是比如 `src/app/main.ts`：
`app.ts` 是这个项目存在最久的文件，外部引用它的地方不少；
而 `app/` 作为一个**模块集合**的语义也正好成立。
TypeScript 里 `import … from './app'` 会解析到 `app.ts`（文件优先），
本项目**没有**这样的裸导入 —— 全部写成显式的 `./app/selftest-hooks` 这样的具体路径，
所以不存在歧义。新增模块时照此约定：放进 `src/app/`，用具体路径引用。

## 3. 五个视图，一份数据

主题（长期领域，可嵌套）、阶段（带起止月份的时段）、时间，三个维度盖在**同一份数据**上。
五个视图只是这份数据的五种读法：

| 视图 | 回答的问题 |
|---|---|
| 画布 | 结构长什么样 |
| 时间轴 | 先后与取代链 |
| 列表 | 清单（可搜索、可筛） |
| 今日 | 当天要做什么 |
| 周历 | 一周一周地回看 |

**周画布**是独立空间：一周一块画布，可以把主画布这一周的记录**复制**进来
（原件不动，副本可以随便改，副本记得来源能跳回原件）。

## 4. 关键架构决策

下面是**推翻了会很贵**的那几条。完整清单在开发期的内部文档里，这里只留
对外读者真正需要知道的。

### AD-01　不用通用白板库，自己写渲染层

不用 tldraw / Konva / React Flow / Fabric / Excalidraw。

理由有两条，第二条是决定性的：

1. **对象模型冲突**。白板库的底层假设是"画布上是一堆自由图形"，而这里的对象是
   **有语义约束的图谱节点**：`取代` 只能从目标连出、`属于` 根本不是一条边（归属
   由主题 / 阶段决定）、点可以同时属于多个主题。这些约束跟"任意图形自由连线"
   的模型正面冲突，最后会变成一连串持续的 hack。
2. **坐标系假设冲突**。白板库是"一张画布 = 一个项目"；这里是"一张画布 = 一个
   主题 / 阶段的视角"。库越灵活，这两处模型差异越难在外部改。

**代价**：视口变换、空间索引、命中检测、文本排版要自己写，约 2000 行。
**缓解**：这块高度独立（world 坐标 + 视口状态 → 像素），没有业务耦合，可单独测试；
将来换 WebGL 只需替换这一层。

### AD-02　画布用 Canvas 2D，不用 SVG

1 万节点 ≈ 4 万次绘制调用。SVG 会产生 4 万个 DOM 节点，合成层压力先于绘制成为瓶颈。
Canvas 2D 走单次 GPU 合成，配合空间裁剪，渲染预算 < 8ms/帧。

**代价**：失去 SVG 免费给的命中检测和 CSS 样式，得自己实现。

### AD-03　搜索自建 CJK bigram 倒排索引

不用 FlexSearch / MiniSearch / Lunr。主流 JS 搜索引擎的默认分词器对中文支持很弱
（有的要用户自带分词器，有的在长查询上召回不稳）。

做法：对每条文本生成所有相邻 2 字组合写进倒排表；查询串同样切 bigram，求交集排序
（命中 gram 数降序 + 原文覆盖率加权），命中后回原文取片段做高亮。

**代价**：索引约为原文的 3–5 倍（10 万字 ≈ 50 万 gram 条目，内存 20–30MB）。
个人使用规模可接受。**否决** jieba 词库：体积大、更新难，对短文本收益低，
而且会让搜索从"确定性"变成"依赖外部词表"。

### AD-04　加密按记录粒度，明文只留索引键

每条记录独立 AES-GCM-256 加密后存 IndexedDB；明文只保留 `id`、`updatedAt` 和
**类型码**（不解密也能按类型筛选）。

整库单 blob 加密会让每次编辑都要重写全库；按记录加密才能增量写。

**已知泄漏（UI 里必须告知用户）**：存储体积、每条记录的创建 / 修改时间、每个点的
**类型**。内容、正文、关系、时间值本身不泄漏。

### AD-05　密钥派生用 PBKDF2-SHA256，不自研

WebCrypto 原生 `deriveKey`，PBKDF2-SHA256，600,000 次迭代（OWASP 2023 建议值），
每个库 16 字节随机 salt。本机约 0.5–1s，可接受。
自研 Argon2id 需要引 WASM 并拖慢首次解锁，收益不抵。

### AD-06　加密可开关，默认开

默认开启，但能在设置里关掉。关掉之后数据仍不联网、可导出，只是不落加密。

加密层因此是**可选的横切关注点**，不污染数据层。

### AD-07　版本历史 = 自动快照 + 手动里程碑

内容变更（标题 / 状态 / 正文）自动留快照，**必须填原因**；手动里程碑是用户自己标的
"这一步值得记住"。

坐标位置、主题 / 阶段归属、`done` 状态**不进**版本历史 —— 它们不是"内容修改"，
动一下位置就产生一条历史会把这个功能淹掉。

### AD-08　交付形态 = 本地 Web 应用（Vite + 纯静态产物）

`dist/` 是**零外部依赖**的静态产物：不发网络请求、不加载 CDN、字体全走系统栈。
断网照常用。

这一条是产品的卖点，也是隐私承诺的一部分 —— **别破坏它**。

### AD-09　五个视图共享同一个 Store

视图不直接改数据，所有用户交互最终都走 `store`。

### AD-10　时间不建独立的一等维度

时间是一个**属性**，不是一个空间维度。主题与阶段是两个维度，第三个维度是时间。
这样"某个时段的某个主题"用两个筛选条件的交集就能表达，不需要第三套坐标系。

### AD-11　多语言：键是英文 slug，中英文同表

`src/i18n/strings.ts` 里一条就是一条，中英文并排：

```ts
'action.deleteTheme': { zh: '删除主题', en: 'Delete theme' },
```

**为什么不用中文原文当键**（这是本项目改过一次的设计）：

- 改中文措辞**不会打断英文翻译**。旧设计里 `t('删除主题')` 改一个字就等于换键，
  英文会静默失效、界面上冒回中文，而且没有任何报错。
- 键名本身是可读的标识符，一眼能看出作用。
- 加一句文案 = 加**一行**（两种语言并排），翻译的人不用在两个文件之间跳。

**落库的值不翻译**。`node.status` 里存的就是 `进行中` 这样的中文字符串，
用户的库里已经躺着一堆了 —— 翻译它等于数据迁移。显示名走
`src/i18n/contracts.ts` 的对照表，**存进库的永远是原值**。

`npm run i18n` 是守门人：查漏翻、查占位符对不上、查英文值里夹中文、查中文键残留。
`npm run i18n:native` 核对原生壳与 web 侧**共用**的那些 slug 逐字一致。

## 5. 数据流

```
用户交互
   ↓
views/  ── 读 ──→  model/store（内存图谱）
   ↓                ↑
app.ts（事件、状态、原生通道）
   ↓
persist/repository ──→ IndexedDB（逐记录加密）
   ↓
search/indexer.worker（后台建 bigram 倒排索引）
```

导出走 `persist/export.ts`，产出 JSON / Markdown / JSON Canvas 三种 —— 结构见
[`DATA-FORMAT.md`](DATA-FORMAT.md)。

## 6. 性能

1440×900，Chromium，1 万节点 / 1 万边（聚簇图库）：

| 指标 | 目标 | 实测 |
|---|---|---|
| 平移缩放帧耗时（全览 8%，全部可见） | < 8 ms | 中位 9.5 ms / P95 14.1 ms |
| 搜索输入 → 高亮 | < 16 ms | 2–20 ms |
| 冷启动到可交互 | < 1.5 s | 1.30–1.94 s |

**「帧耗时 < 8ms」这条在真实聚簇图库下没达到。** 早期版本报的"6.6ms 达标"是量在
**随机长边图**上的 —— 每点平均 1 条边且横跨全图，边的裁剪永远命中，不真实。
换成聚簇图库（每点 1.6 条边、边连邻近节点）后数字才涨上来。

测量方法有两个坑，踩过：必须丢弃预热帧；必须直接打点而不是读上一帧的显示值。

## 7. 隐私边界（能核对的）

- **没有账号、没有服务器、没有广告、不做遥测。** 不是承诺，是可以逐行核对的：
  ```bash
  grep -rnE "fetch\(|XMLHttpRequest|WebSocket|URLSession" src/ macos/
  ```
- 全仓**只有一处**对外请求：节点上贴了**图片 URL**（贴 URL 的封面图不持久）时，
  生成复盘卡片会把那张图拉下来画进 PNG。地址是用户自己给的，只在用户点生成时发生。
- 数据只在这台机器上，用主密码派生的密钥逐条加密。忘了主密码 = 数据没了，
  没有后门，也没有找回流程。
